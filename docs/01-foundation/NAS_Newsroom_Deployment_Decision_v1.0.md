## مسار النشر المعتمد

1. تُبرمج الأداة داخل مستودع GitHub الرسمي.
2. يُربط مستودع GitHub بخدمة النشر المناسبة في Cloudflare.
3. تُنشر بيئة الإنتاج على `nasfm.info`.
4. تُدار سجلات DNS وشهادة HTTPS والحماية من Cloudflare.
5. يبقى GoDaddy جهة تسجيل الدومين، ما لم يُتخذ قرار لاحق بنقل التسجيل.

## فصل المكونات

### الواجهة

تطبيق الويب المتجاوب الذي يستخدمه المحرر. يمكن نشر ملفات الواجهة عبر Cloudflare Pages أو خدمة Cloudflare المناسبة عند اختيار التقنية النهائية.

### الخلفية

المصادقة، جلسات الدخول، مفاتيح API، طلبات الذكاء الاصطناعي، حفظ الأخبار وسجل التعديلات يجب أن تعمل من جهة الخادم، ولا تُوضع أسرارها داخل كود المتصفح.

### البيانات

تُحدد قاعدة البيانات وخدمة التخزين عند اعتماد المواصفات التقنية. لا يعني ربط المستودع بـCloudflare أن قاعدة البيانات والمصادقة أصبحتا جاهزتين تلقائيًا.

## شروط ما قبل الإنتاج

- ربط الدومين بـCloudflare بصورة صحيحة.
- تفعيل HTTPS فقط.
- منع كشف مفاتيح API في المتصفح.
- إعداد متغيرات البيئة في منصة النشر.
- فصل بيئة الاختبار عن الإنتاج.
- اختبار تسجيل الدخول والحفظ والاسترجاع والفشل قبل توجيه الدومين النهائي.
- توثيق آلية النسخ الاحتياطي واستعادة البيانات.

## قرار مؤجل

لم يُحسم بعد مكوّن الاستضافة الخلفية وقاعدة البيانات. يُتخذ القرار بعد اعتماد المواصفات التقنية، مع تفضيل أبسط بنية تحقق الأمان ومتطلبات الـMVP من دون توسيع غير ضروري.

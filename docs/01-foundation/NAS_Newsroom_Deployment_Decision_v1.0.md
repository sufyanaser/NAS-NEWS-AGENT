# قرار الاستضافة والنشر — NAS Newsroom

**الحالة:** معتمد مبدئيًا
**الإصدار:** 1.0
**التاريخ:** 11 أكتوبر 2026

## الأصول الرسمية

- **الدومين الجذر:** `nasfm.info` — مخصص للموقع العام لإذاعة NAS FM
- **عنوان تطبيق التحرير الإخباري (Newsroom):** `nr.nasfm.info` — تطبيق تحرير إخباري داخلي خاص
- **مسجل الدومين:** GoDaddy
- **مزود DNS الموثوق:** Cloudflare — بعد اكتمال التفعيل والتحقق الفعلي (لم يُتحقق منه بعد، انظر «سجل القرار»)
- **استضافة التطبيق:** Cloudflare Workers
- **قاعدة البيانات:** Cloudflare D1
- **مستودع الكود:** `https://github.com/sufyanaser/NAS-NEWS-AGENT`
- **عنوان الإنتاج المعتمد للتخطيط:** `https://nr.nasfm.info` (الموقع العام يبقى `https://nasfm.info`)
- **النشر الإنتاجي:** ممنوع قبل اجتياز اختبارات القبول واعتماد الإصدار
- **مجلد العمل المحلي:** `H:\Projects\NAS-NEWS-AGENT`

## مسار النشر المعتمد

1. تُبرمج الأداة داخل مستودع GitHub الرسمي.
2. يُربط مستودع GitHub بخدمة النشر المناسبة في Cloudflare.
3. تُنشر بيئة الإنتاج على `nr.nasfm.info` (وليس على `nasfm.info` الجذر).
4. تُدار سجلات DNS وشهادة HTTPS والحماية من Cloudflare.
5. يبقى GoDaddy جهة تسجيل الدومين، ما لم يُتخذ قرار لاحق بنقل التسجيل.

## سجل القرار — عنوان تطبيق التحرير

| البند | القيمة |
|---|---|
| القرار السابق | `newsroom.nasfm.info` — كان اقتراحاً غير نهائي (المواصفات الفنية §15.1) |
| القرار النهائي | `nr.nasfm.info` |
| سبب الاختيار | عنوان مختصر وواضح ومستقل عن الموقع العام |
| تاريخ القرار | 2026-10-11 |
| الحالة | Approved for planning, not deployed |

ملاحظات ملزمة لهذا القرار:

- جلسة المحرر (`nas_session`) كوكي Host-only على `nr.nasfm.info` دون `Domain=.nasfm.info`، فلا تُشارك مع الموقع العام أو نطاقات فرعية أخرى.
- لا يُفعَّل CORS لأي Origin خارجي دون متطلب موثق.
- لا `includeSubDomains` في HSTS على نطاق الجذر.
- تفويض Nameservers إلى Cloudflare غير مثبت؛ لا يُعتبر مكتملاً دون تحقق حديث، ولا يجري أي تغيير DNS إلا ضمن مرحلة نشر مستقلة.

## فصل المكونات

### الواجهة

تطبيق الويب المتجاوب الذي يستخدمه المحرر. يُقدَّم عبر Cloudflare Workers Static Assets ضمن Worker واحد مع مسارات `/api/*` (انظر المواصفات الفنية §1).

### الخلفية

المصادقة، جلسات الدخول، مفاتيح API، طلبات الذكاء الاصطناعي، حفظ الأخبار وسجل التعديلات يجب أن تعمل من جهة الخادم، ولا تُوضع أسرارها داخل كود المتصفح.

### البيانات

تُحدد قاعدة البيانات وخدمة التخزين عند اعتماد المواصفات التقنية. لا يعني ربط المستودع بـCloudflare أن قاعدة البيانات والمصادقة أصبحتا جاهزتين تلقائيًا.

## شروط ما قبل الإنتاج

- ربط الدومين بـCloudflare بصورة صحيحة.
- تفعيل HTTPS فقط.
- منع كشف مفاتيح API في المتصفح.
- إعداد متغيرات البيئة في منصة النشر.
- فصل بيئة الاختبار عن الإنتاج.
- اختبار تسجيل الدخول والحفظ والاسترجاع والفشل قبل توجيه الدومين النهائي.
- توثيق آلية النسخ الاحتياطي واستعادة البيانات.

## قرار مؤجل

حُدّد مكوّن الاستضافة الخلفية وقاعدة البيانات بعد اعتماد المواصفات التقنية: Cloudflare Workers وCloudflare D1 (انظر `docs/02-requirements/NAS_Newsroom_Technical_Specs_v1.0.md`). يبقى معلّقاً: مزوّد الموديل وسياسة الاحتفاظ بالبيانات، وموقع D1، وعنوان Staging المعتمد؛ ولا يُنشأ أي مورد Cloudflare قبل مرحلة النشر المعتمدة.
